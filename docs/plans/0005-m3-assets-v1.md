# 0005 — M3: Assets v1

**Status:** done 2026-11-04 (textures: RGBA8 + mips now, BC encoding at M10; platforms: Windows only) · **Milestone:** M3 (CLAUDE.md §9, lore §8)

**Deviations from this plan:**
- **Handles keep the whole source alive.** A strong `Handle` counts references to its *source file*, not to the single sub-asset: spawned model parts store only weak `AssetId`s, and the `SceneRoot`'s handle keeps every mesh, material and texture of the file loaded. One counter per file, no per-sub-asset bookkeeping.
- **glTF buffers and images are resolved by our importer** (GLB blob, base64 `data:` URIs, files next to the `.gltf`), with the `gltf` crate's `import` feature off. Every external file is then part of the DDC key and of hot reload, and no second `image`/`base64` dependency comes in.
- **Our KTX2 writer** (fixtures) emits a minimal DFD, just its 4-byte size; our reader takes the format from `vkFormat`.
- **An inline `Material` overrides only factors.** The asset's textures stay applied ("Override Material" in the editor).
- **Clicking any part of a model selects the instance root** (Blender's collection-instance behavior); the parts are reachable through the outliner. Selection boxes use the asset's imported bounds.
- **F3 search matches every word** ("model crate" finds "Add › Model › models/crate.glb"), and lists registry models.
- **glTF sampler wrap/filter modes are ignored in v1:** every material texture uses linear, mipmapped, 8× anisotropic, repeat sampling.
- **The textured-quad test** asserts on pixels in `crates/ge_render/tests/passes.rs`, like the other pass tests, rather than adding a golden image.
- **Test assets are committed.** `assets/models/crate.glb`, `assets/textures/checker_bc1.ktx2` and their `.meta` files (about 6 KB, generated by `cargo xtask gen-assets`) are in the repo, so a clean clone shows the crate without running a tool first.

## Goal

Content comes from files instead of code. Drop a `.glb` / `.gltf` (with PNG, JPEG or KTX2 textures) into `assets/`, and the engine loads it in the background, gives it a stable GUID, caches the imported result, and swaps it live when the file changes on disk.

**M3 exit criteria** (lore §8):
- an AssetServer with handles;
- async loading;
- glTF meshes, materials and textures (KTX2/BCn);
- `.meta` GUIDs;
- file-watch hot reload;
- a DDC cache.

M3 is done when:
- the sample arena shows a glTF prop with a base-color texture;
- the editor's **Add ▸ Model** lists every model in `assets/`;
- re-exporting that model from Blender updates it in the running editor and game without a restart;
- a second launch loads it from the DDC without re-importing.

## Decisions & assumptions (flagged)

1. **New crate `ge_tasks` (rank 3), kept small.** It provides:
   - `Tasks::io(f)`, which runs blocking file reads on 2 dedicated IO threads;
   - `Tasks::compute(f)`, which runs CPU work (decode, import, mip generation) on a `rayon` pool;
   - both return a `Task<T>` that the main thread **polls** each frame.

   There is no async runtime: the frame loop is never driven by futures (CLAUDE.md §7), and Tokio isn't needed for file IO. The render thread joins this crate at M5.
2. **New crate `ge_asset` (rank 6).** It depends on `ge_core`, `ge_tasks` and `ge_ecs` (for the `AssetServer` resource and events). It owns:
   - asset paths and GUIDs;
   - `.meta` sidecars;
   - the registry;
   - the DDC;
   - the importers;
   - the hot-reload watcher.

   The renderer depends on `ge_asset`'s **asset types** (rank 6 < 7, already allowed).
3. **Handles (lore §6.8):** `Handle<T>` is a **strong, reference-counted** handle (`Arc` around an `AssetId<T>`). `AssetId<T>` is a weak, copyable generational id (ECS components and the render snapshot store this).
   - When the last strong handle drops, the asset is unloaded at the end of the frame.
   - `ge_core::Handle`/`Pool` stay as they are: they're for engine-internal pools.
4. **Asset types in v1:**
   - `Mesh`: positions, normals, UV0, indices, local bounds.
   - `Texture`: format, size, mip chain, and whether it's color (sRGB) or data.
   - `MaterialAsset`: the glTF metallic-roughness model. Base color factor and texture, metallic/roughness factors and texture, emissive factor and texture, plus alpha mode, normal texture and occlusion texture, which are loaded and stored but **not rendered until M4**.
   - `ModelAsset`: the glTF node tree, where each node has a name, a transform and its mesh/material pairs.

   Sub-assets are addressed as `models/crate.glb#Mesh0`, `#Material1`, `#Texture2`.
5. **`.meta` sidecars:** `crate.glb.meta` sits next to its source and is RON with a schema version. It holds `guid` (UUID v4, CLAUDE.md §11), `importer`, `importer_version` and the import `settings` (scale, flip UVs, `srgb` overrides, generate mips).
   - A missing `.meta` is created on first scan.
   - Moving a file **together with** its `.meta` keeps its GUID, so references survive renames.
   - `.meta` files are committed; the DDC is not.
6. **DDC (derived data cache):** stored in `<workspace>/.ddc/`, which is gitignored. The key is `blake3(source bytes ‖ dependency bytes ‖ settings RON ‖ importer id ‖ importer version ‖ DDC format version)`. For a `.gltf`, the dependencies are its external `.bin` and image files.
   - Payloads are `postcard` (compact binary, in the §4 stack). Writes are atomic: write to a temp file, then rename.
   - A corrupt entry is logged, deleted and re-imported.
   - `rkyv` is for **cooked** containers at M10, not the DDC.
7. **Texture formats:**
   - **KTX2 files load natively**, including BC1–BC7 payloads with their stored mips. wgpu's `TEXTURE_COMPRESSION_BC` is requested when the adapter has it (every desktop GPU does).
   - PNG and JPEG are decoded and given a full mip chain (sRGB-correct box filter for color, linear for data). They're stored in the DDC as **RGBA8**.
   - **Encoding to BCn is deferred to the cooker (M10)**, so no texture-compression dependency now. *Question 1 below.*
   - KTX2 *zstd supercompression* is not supported in v1: such files give a clear error. *Question 1.*
8. **Renderer changes:**
   - `Vertex` gains `uv: [f32; 2]` (36 → 44 bytes). The procedural cube, plane and every primitive generate UVs.
   - `MeshKind` gains `Asset(AssetId<Mesh>)`, and `MeshRenderer` gains `material: Option<AssetId<MaterialAsset>>`.
   - Precedence: an inline `Material` component (the editor's) overrides the material asset, which overrides the default.
   - The mesh shader gets a **material bind group** (group 2): base color, metallic-roughness and emissive textures, a sampler and material factors.
   - Meshes with no material bind 1×1 white textures, so the **golden image stays identical**.
   - `ge_rhi` gains texture mips, BC formats, sampler address and filter modes, and a mipmap/anisotropic sampler.
9. **Extract stays the only sync point (law 2).** Asset data is shared, never copied each frame:
   - When a mesh or texture is loaded or modified, extract puts its `Arc` into `RenderSnapshot::asset_uploads` **once**. Freed assets go into `asset_frees`.
   - The renderer keeps GPU copies keyed by `(id, version)`.
   - Draw items carry only ids.
10. **Hot reload:** a `notify` watcher on `assets/`, debounced as for shaders, triggers a re-import.
    - The new version replaces the old one atomically (same `AssetId`, version + 1), and `AssetEvent::Modified` fires.
    - Meshes, textures and materials update in place.
    - A model whose **node tree** changed re-spawns its instances (`SceneRoot` entities), and per-instance edits are lost. The log says so; preserving them needs reflection (M6).
11. **Spawning models:** a `SceneRoot(Handle<ModelAsset>)` component. When the model is ready, a system spawns its node tree as children with `Name`, `Transform` and `MeshRenderer`. The outliner then shows the glTF hierarchy.
12. **Editor:**
    - **Add ▸ Model ▸ \<every model in the registry\>** replaces today's greyed "Import glTF…". No file dialog: you drop files into `assets/`, and the list refreshes when the watcher sees them.
    - The Mesh tab shows the asset path, GUID, vertex/triangle counts and the import settings (read-only in v1; editing `.meta` in the UI comes at M6).
    - The Material tab shows the asset's values, with **Override** to copy them into an editable inline `Material`.
    - "Import glTF" was marked Planned (M3) in the settings schema; it becomes Live.
13. **Test assets are generated, not downloaded.** `cargo xtask gen-assets` writes a small `crate.glb` (a textured box with two materials and a child node) and a `checker_bc1.ktx2` into `assets/` from code we own, so there are no third-party licenses. Any glTF you export from Blender works too.
14. **Platforms (the CLAUDE.md §11 decision due at M3):** **Windows only.** File watching, IO threads and native file paths are assumed. A WASM/WebGPU build is not kept compiling; revisit if a web demo is ever wanted. *Question 2.*

## Acceptance criteria (M3 exit criteria)

- [ ] `cargo xtask ci` passes. The rank table includes `ge_tasks` and `ge_asset`, and `cargo tree -d` shows no new duplicate of `wgpu`, `winit` or `glam` 0.34.
- [ ] **Handles:** loading the same path twice returns the same id. Dropping the last strong handle unloads the asset, and a weak `AssetId` then resolves to `None`.
- [ ] **Async:** `load()` returns immediately (the test asserts it doesn't block). The asset becomes `Loaded` after polling, and the frame loop never waits on IO.
- [ ] **glTF:** the generated `crate.glb` imports with the expected mesh/material/texture counts, material factors, texture size and mip count, and node hierarchy and transforms. A `.gltf` with an external `.bin` and PNG works the same.
- [ ] **KTX2:** `checker_bc1.ktx2` loads as a BC1 sRGB texture with all its mips. A zstd-supercompressed file gives a readable error, not a panic.
- [ ] **`.meta`:** it's created with a v4 GUID on first scan. Renaming the source together with its `.meta` keeps the GUID, and the registry resolves GUID ↔ path both ways.
- [ ] **DDC:** the second load of an unchanged asset is a cache hit (a counter in the test), with no import. Changing a setting, the importer version or the source bytes misses. A truncated DDC file is re-imported.
- [ ] **Hot reload:** rewriting the source file bumps the asset's version and fires `Modified`. The reimport path is unit-tested, and the watcher has an integration test with a temporary directory.
- [ ] **Rendering:** the golden image is unchanged. A new pass test draws a textured quad (checker texture sampled with mips) and checks pixels. The sample arena shows the crate prop textured in both `game` and `editor`.
- [ ] **Editor:** Add ▸ Model spawns the crate with its node hierarchy in the outliner. Undo removes it. The Mesh tab shows path, GUID and counts.

## Manual test steps

1. Run `cargo xtask gen-assets`. Then run `cargo run -p game`: the crate prop is visible and textured in the arena. The log shows `imported models/crate.glb` (first run) and `asset ready … ddc=miss`.
2. Close the game and run it again. The log shows `ddc=hit`, and the prop appears with no import.
3. Run `cargo run -p editor`. Add ▸ Model ▸ crate: it spawns, and the outliner shows its child nodes.
4. Export any model from Blender as `.glb` into `assets/models/`. Within about a second it appears under Add ▸ Model, and a `.meta` file appears next to it.
5. With that model in the scene, re-export it with a changed material color from Blender. The editor updates it without a restart.
6. Rename `assets/models/crate.glb` and its `.meta` together, then restart. The sample still finds the crate by GUID.
